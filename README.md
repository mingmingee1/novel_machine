# 여백 — 개인 소설 작업실

휴대폰에서 읽고 쓰는 개인용 인터랙티브 소설 작성기입니다. React·TypeScript 화면, Node.js 서버와 SQLite를 사용합니다. 작품의 기준은 서버 DB이며, 브라우저는 읽기 캐시·초안·표시 설정을 보관합니다.

## 실행

**Tailscale로 휴대폰에서 사용하려면** PC와 휴대폰을 같은 Tailscale 계정으로 연결하고, Windows에서는 `start-tailscale.cmd`를 실행하세요. Mac/Linux에서는 `node scripts/start-tailscale.mjs`를 실행합니다. 패키지 설치·빌드·개인망 HTTPS 연결을 준비한 뒤 휴대폰에서 열 주소와 앱 암호를 표시합니다. 자세한 순서는 [시작하기.txt](시작하기.txt)에 있습니다. PC와 실행 창은 켜 두어야 합니다.

Node.js **24.19 이상**이 필요합니다. 이 환경에서 검증한 버전은 `24.19.0`입니다. 저장소 루트에서 실행하세요.

```sh
npm ci
npm run build
npm start
```

기본 호스트는 `127.0.0.1`, 포트는 `4317`입니다. 실행 중인 PC의 브라우저 주소창에 해당 호스트와 포트를 입력합니다. 개발 중에는 `npm run dev`를 사용합니다. Vite와 API가 한 서버에서 실행됩니다.

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
npm run smoke
```

`test:browser`는 임시 DB와 모의 Provider를 사용합니다. 유료 모델 호출이 없습니다. Linux의 `/usr/bin/chromium`을 우선 사용하며, 다른 PC에서는 `npx playwright install chromium`으로 테스트 브라우저를 준비하거나 `NOVEL_CHROMIUM_PATH`를 설정합니다. `smoke`는 실행 중인 서버를 점검하며 작품 데이터를 수정하지 않습니다.

## 처음 사용하기

1. **첫 번째 작품 시작하기**에서 제목을 정합니다. 설정 탭에서 인물·세계관을 기록하고 적용 범위를 정해 적용합니다.
2. **연결 설정**에서 CLI 설치·인증 또는 API 키 설정 여부를 확인합니다. 입력창에서 연결과 실제 계정이 지원하는 모델을 선택합니다.
3. 소설 탭에 첫 장면을 입력합니다. 결과는 미확정 후보로 보존됩니다. 본문과 변경안을 검토한 다음 **이 장면 확정** 또는 이어쓰기·선택지로 확정합니다.
4. 재작성·부분 수정·문체 재작성은 같은 이전 상태에서 새 후보를 만듭니다. 이전 후보는 보관함에서 비교·복원할 수 있습니다. 문단 옆 자물쇠로 잠금을 설정합니다.
5. 확정된 과거 장면을 고치려면 **이 장면 전에서 분기**를 사용합니다. 영향받는 후속 장면·기억 수를 확인한 뒤 기존 원문을 새 분기의 수정 후보로 가져옵니다. 기존 본편은 보존됩니다.

소설, 설정 상담, OOC는 별도 기록입니다. 설정·OOC 대화는 자동으로 정본을 바꾸지 않습니다. 대화의 **이번 생성에 적용**, **현재 장면에 적용**, **설정 변경안 저장**으로 적용 의도를 명시합니다. 입력창의 범위 선택은 해당 요청의 의도이며, 지속되는 설정은 설정 탭에서 명시적으로 저장·적용합니다.

## 문체 자료 → 실제 적용

1. **문체 자료실 → 원문·예문**에서 TXT·Markdown 파일이나 직접 쓴 글을 등록합니다.
2. 원문 카드를 열어 드래그로 구간을 선택하고, 좋아하는/피할 예문과 요소·장면 태그를 저장합니다. 원문 전체를 임의로 몇 문장으로 잘라내지 않습니다.
3. **문체 프로필**에서 근거 예문과 실행 규칙을 연결합니다. 또는 원문 상세에서 현재 선택한 연결로 분석을 실행합니다. 문장 길이 등 통계는 코드 계산이며 문학적 해석은 모델 의견입니다.
4. 집필 입력창에서 `프로필 중심` 또는 `프로필 + 예문`을 선택하고 고급 설정에서 프로필·강도를 정합니다. 서술·대사·내면·묘사별 프로필도 지정할 수 있습니다. 문체 프로필 화면의 ‘인물·장면별 문체 자동 연결’에서 작품 공통·시점 인물·등장인물 말투·장면 유형 조건을 등록하면 이후 요청에 연결한 프로필의 현재 버전이 포함됩니다.
5. 생성 결과의 **사용 근거**에서 실제 입력에 포함된 예문 ID, 프로필 버전, 기억, 예산을 확인합니다. 진행 중 자료가 바뀌어도 입력 고정본은 바뀌지 않습니다.
6. **문체 실험실**에서 같은 개요로 A/B 두 후보를 명시적으로 생성합니다. 이름을 가린 비교가 가능하며, 선택 전에는 정본과 기억을 바꾸지 않습니다. 선호는 장면 피드백으로 기록되고 일반 규칙으로 자동 승격되지 않습니다.

문체 적용은 프로필·예문·피드백 방식입니다. 파인튜닝이나 정의되지 않은 ‘문체 일치율’을 제공하지 않습니다. 예문 중복 탐지와 사람의 전후 비교를 함께 사용합니다.

## 연결 준비

`.env.example`을 `.env`로 복사해 필요한 값만 채웁니다. `.env`와 `data/`는 Git에서 제외됩니다. 비밀값은 서버 프로세스에서만 사용하며 응답·번들·작품 백업에 포함하지 않습니다.

| 연결       | 준비                                            | 모델 입력                        | 구현 경로                                             |
| ---------- | ----------------------------------------------- | -------------------------------- | ----------------------------------------------------- |
| Codex CLI  | 공식 CLI 설치 후 같은 OS 계정에서 `codex login` | `default` 또는 지원 모델 이름    | `codex exec`, stdin, 새 임시 폴더, JSONL              |
| Gemini CLI | 공식 CLI 설치 후 같은 OS 계정에서 로그인        | 계정에서 지원하는 모델 이름/별칭 | `gemini --prompt`, stdin, stream-json, 도구 거부 정책 |
| OpenAI API | `NOVEL_OPENAI_API_KEY`                          | 계정에서 접근 가능한 모델        | Responses API 스트림                                  |
| Gemini API | `NOVEL_GEMINI_API_KEY`                          | 계정에서 접근 가능한 모델        | generateContent SSE                                   |

기존 `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY`도 서버에서 읽을 수 있습니다. 클라우드 비밀 바인딩에는 플랫폼 예약 이름 대신 `NOVEL_OPENAI_API_KEY`·`NOVEL_GEMINI_API_KEY`를 사용합니다. API 키는 환경 설정의 보안 입력란이나 개인 PC의 `.env`에 넣으세요.

CLI 설치 예:

```sh
npm install -g @openai/codex
npm install -g @google/gemini-cli
codex --version
codex login
gemini --version
gemini
```

Codex `0.163.0`, Gemini CLI `0.65.0`의 도움말과 공식 소스 문서를 확인해 구현했습니다. 명령 실행에 `shell: true`를 사용하지 않습니다. 실행 파일을 바꾸려면 `NOVEL_CODEX_PATH` 또는 `NOVEL_GEMINI_PATH`에 **인자가 없는 실행 파일 경로**를 설정합니다. `.js` 경로는 Node로 실행됩니다. CLI 도구와 확장을 제한하지만, 같은 OS 계정의 CLI 프로세스 자체를 별도 VM처럼 완전히 격리하지는 않습니다. 이 앱은 로컬 개인 사용을 전제로 합니다.

현재 클라우드에서는 Codex 설치·로그인은 확인됐지만 기본 샌드박스에서 실행 디렉터리 초기화가 실패했습니다. 승인된 별도 실행 검사에서도 정상 생성 응답을 확인하지 못했습니다. 기존 로그인은 유지되며 새 토큰이 필요하다고 판단하지 않았습니다. Gemini CLI는 설치와 도움말만 확인했고 로그인 인증은 제공되지 않았습니다. API 키도 없어 실제 API 생성은 미검증입니다. 모의 연결 성공을 실모델 생성·문학적 품질 검증으로 보고하지 않습니다.

네트워크가 제한된 환경에서 API 연결은 `api.openai.com`, `generativelanguage.googleapis.com`이 필요합니다. CLI 로그인·모델 요청은 선택한 계정과 CLI의 공식 네트워크 요구사항을 따라야 합니다. 공개 배포·공유기 포트 개방은 수행하지 않습니다.

Set-Location C:\path\to\novel_machine

Copy-Item .env.example .env   # .env가 이미 있으면 보존하고 필요한 항목만 편집

PowerShell에서 환경 변수를 쓰려면 `$env:NOVEL_PORT = '4317'`처럼 설정합니다. `NODE_ENV` 등 공통 환경 값을 다른 의미로 바꾸지 않습니다.

Windows에서는 `.cmd` 래퍼가 `shell: false` 실행을 지원하지 않을 수 있습니다. Gemini의 전역 설치 경로를 확인한 뒤 `.env`의 `NOVEL_GEMINI_PATH`를 `C:/Users/<사용자>/AppData/Roaming/npm/node_modules/@google/gemini-cli/bundle/gemini.js`처럼 실제 JS 진입점으로 지정합니다. 설치 위치는 `npm root -g`로 확인하세요. Codex는 공식 네이티브 실행 파일 또는 패키지의 실제 JS 진입점을 지정합니다. Windows 실기기 실행은 이 Linux 클라우드에서 검증하지 않았습니다.

## 휴대폰 개인망 접속과 오프라인

### Tailscale로 연결

`start-tailscale.cmd` 또는 `npm run start:tailscale`은 로그인된 기기의 Tailscale DNS 주소를 읽어 **Tailscale Serve의 HTTPS 8443 포트**로 연결합니다. 처음 실행할 때 `node scripts/start-tailscale.mjs`를 사용하면 npm 설치도 자동 처리합니다. 이미 사용 중인 8443 포트나 공개 Funnel 설정을 발견하면 기존 구성을 보존하고 중단합니다. HTTPS를 처음 쓰는 계정은 Tailscale이 안내하는 관리 화면에서 활성화한 뒤 다시 실행하세요.

앱 서버는 `127.0.0.1:4317`에만 바인딩하며 `NOVEL_PUBLIC_ORIGIN`에 정확한 휴대폰 접속 주소를 지정합니다. 브라우저는 해당 HTTPS 주소와 일치하는 출처로 요청하고 Secure 세션 쿠키로 인증합니다. 접속 암호는 `.env`의 `NOVEL_ACCESS_TOKEN`을 우선 사용하며 없으면 `.env.tailscale.local`에 생성합니다. 이 파일은 Git과 배포 ZIP에서 제외해야 합니다.

휴대폰에서 Tailscale을 켜고 실행 창의 주소를 열어 표시된 암호를 입력하세요. iPhone Safari의 공유 → 홈 화면에 추가, Android Chrome의 메뉴 → 홈 화면에 추가로 바로가기를 만들 수 있습니다. 휴대폰에는 Node.js나 Codex CLI를 설치하지 않습니다. CLI 로그인과 모델 호출은 PC/서버에서 처리합니다. Tailscale 접근 정책이 있는 계정에서는 휴대폰에서 해당 기기의 8443 포트로 접속할 수 있어야 합니다.

수동 설정이 필요하면 `.env`에 `NOVEL_HOST=127.0.0.1`, `NOVEL_PUBLIC_ORIGIN=https://기기.테일넷.ts.net:8443`, 20자 이상의 `NOVEL_ACCESS_TOKEN`을 지정한 뒤 `npm start`를 실행합니다. 별도 터미널에서 `tailscale serve --bg --https=8443 http://127.0.0.1:4317`을 실행합니다. 앱 종료 후 Serve 설정은 남으며 제거 명령은 `tailscale serve --https=8443 off`입니다. 공개 Funnel이나 공유기 포트 개방은 필요하지 않습니다.

### 다른 개인망과 오프라인

기본값은 로컬 접근입니다. 같은 신뢰할 수 있는 개인망에서 휴대폰으로 접속하려면 `.env`에 `NOVEL_HOST=0.0.0.0`과 20자 이상의 임의 `NOVEL_ACCESS_TOKEN`을 설정하고 서버를 재시작합니다. 휴대폰에서는 PC의 사설 IP와 설정한 포트를 사용합니다. 첫 접속에 암호가 필요하고 세션 쿠키·CSRF 검증으로 데이터와 CLI 요청을 보호합니다.

사설 IP의 일반 HTTP는 전송 암호화를 제공하지 않습니다. 신뢰할 수 있는 개인망에서만 사용하거나 직접 관리하는 HTTPS/개인망 접근 방법을 적용하세요. 앱이 VPN이나 외부 터널을 자동 설치하지 않습니다.

오프라인 읽기는 이미 방문해 캐시된 작품, 입력 초안, 기기별 읽기 설정에 한정됩니다. 서비스 워커 설치와 오프라인 새로고침은 localhost 또는 HTTPS의 보안 컨텍스트에서 가능합니다. 일반 사설 IP HTTP에서는 브라우저가 서비스 워커를 차단하므로 이미 열린 화면의 초안 보존만 기대해야 합니다. PC가 꺼진 동안 모델 생성을 제공하지 않습니다. 재연결 때 초안을 자동 전송하지 않으며 기준 버전이 바뀌면 확인을 요구합니다.

320px 폭, 200% 글자 확대, 한글 조합 Enter, 키보드 높이를 흉내 낸 뷰포트 축소를 Chromium에서 검사했습니다. 실제 iOS/Android 키보드·한국어 시스템 글꼴은 별도 기기 검증이 필요합니다.

## 백업·복원과 데이터

`data/novel.sqlite`가 기본 DB이며 WAL 모드를 사용합니다. 첫 시작에 `server/migrations/001_initial.sql`이 적용됩니다. 다른 위치는 `NOVEL_DATA_DIR`로 지정합니다. 실행 중 DB 파일만 복사하기보다 앱의 전체 백업을 사용하세요.

**가져오기·백업 → 전체 백업**은 작품·분기·원문·후보·기억·설정·문체·피드백·작업 입력과 결과를 버전 및 SHA-256 검증값과 함께 저장합니다. 복원은 무결성과 주요 참조를 검사하고 모든 ID를 새로 매핑해 별도 작품으로 만듭니다. 진행 중이던 외부 작업은 `interrupted`로 복원하고 자동 재실행하지 않습니다. 부분 출력은 작업 기록에서 열람할 수 있습니다. 세션 쿠키와 API 키는 백업 대상이 아닙니다.

본문 TXT·Markdown 내보내기에서 정본만 또는 최신 미확정 후보 포함을 고릅니다. 후보에는 표시가 붙습니다. 여섯 영역 전체 내보내기도 지원합니다. 가져온 원문은 보존되며 분류 미리보기 후 선택한 본문을 후보로 저장합니다.

인물·세계관 가져오기는 설정 탭에서 JSON 배열을 읽어 모두 **제안**으로 저장합니다. 예:

```json
[
  {
    "kind": "character",
    "name": "민서",
    "text": "도서관에서 일한다.",
    "aliases": ["민서 씨"]
  }
]
```

검색은 작품·분기의 정본 ID를 먼저 제한한 뒤 인물 별칭과 한국어 조사 부착 문자열을 조회합니다. 별도 임베딩 전송·과금은 없습니다. 검색 자료는 원문과 기억에서 다시 만들 수 있는 파생 정보이며, 원본 기억을 바꾸지 않습니다.

## 구조와 검증 자료

- `shared/domain.ts`: 화면·서버 공통 스키마, 기억 종류, 요청과 후보 타입
- `server/service.ts`: 후보 확정·분기·설정·백업 서비스
- `server/context.ts`, `validation.ts`: 검색·예산·문체 입력·근거 검증
- `server/jobs.ts`, `providers.ts`: 영속 작업, 중단·재시도, 네 연결 어댑터
- `server/api.ts`: 개인 세션, CSRF, REST·SSE
- `src/`: 집필·상담·기억·문체·백업 화면
